A) Закрытые проблемы
---------------------
1. Создан reusable компонент ExpandableCard.
   - Новый файл: core/ui/src/main/java/com/herocraft24/core/ui/render/ExpandableCard.kt
   - Реализует карточку с заголовком, опциональным подзаголовком и сворачиваемым телом.
   - Поддерживает сохранение состояния раскрытия через openId + openIdsSet.
   - Поддерживает ленивую инициализацию контента через onExpand.

2. Заменены 7 методов создания карточек в ReferenceDetailFragment на ExpandableCard:
   • createClassSubclassCard
   • createMetamagicCard
   • createManeuversCard
   • createSchemsCard
   • createInvocationCard
   • createFeatureCard
   • createSpeciesTraitCard
   - Удалён дублирующий код MaterialCardView/LinearLayout/TextView.
   - Состояния раскрытия (openClassSubclassIds, openMetamagicIds, openManeuversIds,
     openSchemsIds, openInvocationIds, openFeatureIds, openSpeciesTraitIds)
     перенесены в ExpandableCard.

3. Реорганизован renderMonster().
   - Блок описания перенесён после quick_stats и ability_scores.
   - Теперь порядок: ключевые характеристики → характеристики → описание → навыки и прочее.

B) Оставшиеся проблемы
-----------------------
1. createFeatureCard всё ещё имеет сложную логику ленивого linkify описания,
   реализованную через placeholder и onExpand. Это работает, но остаётся
   неидеальным: придётся поддерживать, если изменится структура Feature.
2. Секция "Таблица" и description2 в renderMonster() идут после всех разделов
   действий, что не изменилось и остаётся вне scope текущей фазы.
3. UI enum-классы (SpellSchool, ItemCategory и др.) по-прежнему не используются
   в адаптерах и фильтрах.

C) Новые риски
--------------
1. ExpandableCard использует MutableSet<String> для персистенции состояния.
   Если несколько экранов будут делить один и тот же openIdsSet, возможны
   конфликты id — нужно следить за уникальностью openId.
2. createFeatureCard возвращает Pair<MaterialCardView, LinearLayout>, но в некоторых
   местах второй элемент не используется. Это оставлено для совместимости с
   существующим API.
3. Переход на ExpandableCard унифицировал визуальное оформление карточек,
   но любое изменение в ExpandableCard теперь влияет на все экраны деталей.

D) Что оставить как есть
-------------------------
1. createFeatureCard сохраняет свою логику ленивого linkify через onExpand,
   чтобы не потерять оптимизацию при первом раскрытии.
2. renderMonster оставлен с текущим порядком секций; остальные блоки
   (языки, среда, сокровища, действия) не трогались.
3. Остальные карточки (class subclass, metamagic, maneuvers, schems, invocation,
   species traits) теперь используют общий компонент и визуально единообразны.

E) Следующая очередь работ
---------------------------
1. Начать использовать UI enum-классы (SpellSchool, ItemCategory, ItemRarity,
   CreatureSize, CreatureType) в фильтрах и адаптерах.
2. Заменить deprecated getParcelable() в ReferenceListFragment на современный API.
3. Рассмотреть удаление/очистку старых batch-репортов из корня проекта.
4. Провести дополнительный ручный тест UI на экранах:
   класс → подклассы, приёмы, схемы, призывы, черты видов.
