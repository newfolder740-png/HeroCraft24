Аудит JSON-ассетов HeroCraft24
==============================
Дата: 2026-08-08
Источники: 01_architecture_report.txt, 02_model_audit.txt, 03_ui_render_audit.txt,
           прямой анализ 2771 JSON-файлов в assets/packs/phb2024/
           анализ manifest.json (2695 записей в 11 категориях)


A) Форматные проблемы
----------------------

1. source.abbreviation — 3 разных формата для одного источника
   Затронуты: ВСЕ JSON-файлы всех категорий
   Проблема: Поле source.abbreviation для одной и той же книги
   (Player's Handbook 2024) записано тремя способами:
     "PHB2024"     — в items/* (685 файлов), classes/* (13 файлов)
     "PHB 2024"    — в spells/* (412 файлов), conditions/* (16 файлов),
                     backgrounds/* (61 файл), species/* (19 файлов)
     "MM 2025"     — в monsters/* (633 файла)
   Причина: Нет валидации при создании JSON-файлов; разные
   редакторы использовали разные форматы.
   Следствие: Поиск по source.abbreviation не работает; невозможно
   сгруппировать объекты по источнику без нормализации.

2. source.book.en — 2 формата для одной книги
   Затронуты: spells/*, items/*, classes/*, species/*, conditions/*
   Проблема:
     "Player's Handbook (2024)" — в spells/* (со скобками)
     "Player's Handbook 2024"    — в items/* (без скобок)
   Дополнительно: 2 кодировки апострофа в "Player's":
     \u0027 (Unicode-escaped) — в большинстве backgrounds
     ' (typographic curly)    — в noble.json, entertainer.json, wayfarer.json

3. casting_time — свободный русский текст вместо структуры
   Затронуты: spells/* (412 файлов)
   Проблема: Поле casting_time всегда строка на русском языке,
   смешивающая тип действия, длительность, условие и флаг ритуала:
     "Действие"                    — acid_splash.json
     "Бонусное действие"           — armor_of_agathys.json
     "1 минута или Ритуал"         — alarm.json
     "Реакция, совершаемая вами, когда по вам попадает..." — shield.json
   Нет числового поля для длительности, нет enum для типа действия.
   Следствие: Фильтрация по casting_time требует NLP или lookup-таблицы;
   локализация на английский невозможна без полной переделки.

4. duration — свободный русский текст вместо структуры
   Затронуты: spells/* (412 файлов)
   Проблема: Аналогично casting_time. Поле duration — строка:
     "Мгновенная"
     "Концентрация, вплоть до 1 минуты"
     "24 часа" vs "24 часов" (грамматическая вариация)
   При этом есть отдельное boolean-поле concentration, которое
   дублирует информацию, зашитую в duration.

5. range.type — всегда "range" даже для self/touch
   Затрануты: spells/* (412 файлов)
   Проблема: Все заклинания используют "type": "range" независимо
   от реальной дистанции. Для заклинаний "На себя" (shield.json,
   wish.json) type должен быть "self", но используется "range".
   Поле distance всегда null; реальная дистанция зашита в text.

6. damage_vulnerabilities — русский текст против английских идентификаторов
   Затронуты: monsters/* (28 монстров с vulnerabilities)
   Проблема: damage_vulnerabilities использует русский текст:
     "к урону Огонь"  — ankhtepot.json
     "к урону Дробящий" — skeleton.json
   В ТО ЖЕ ВРЕМЯ damage_resistances, damage_immunities,
   condition_immunities используют английские идентификаторы:
     ["fire"], ["bludgeoning"], ["poisoned"]
   Следствие: Локализация damage_vulnerabilities требует отдельный
   when-блок; нельзя использовать единый localizeDamageType().

7. damage_vulnerabilities — массив содержит описания вместо типов
   Затронуты: shadow.json, rakshasa.json
   Проблема: В shadow.json массив содержит:
     ["к солнечному свету. Находясь под солнечным светом",
      "Тень совершает с Помехой Тесты К20."]
   Это игровой механик-описание, разбитое на 2 элемента массива,
   а не список типов урона.
   Следствие: UI попытается отрендерить это как список типов урона.

8. species.darkvision — 0 вместо null/absent
   Затронуты: 7 из 19 species-файлов (где нет тёмного зрения)
   Проблема: При отсутствии тёмного зрения используется 0, а не null.
   Модель LocalizedString и другие nullable-поля используют null.
   0 vs null создаёт двусмысленность: "darkvision: 0" может означать
   "нет тёмного зрения" или "дальность 0 футов".

9. null vs [] vs absent — несогласованность в monsters
   Затронуты: monsters/* (633 файла)
   Проблема: три разных способа представить "нет данных":
     traits: []              — пустой массив
     bonus_actions: null    — null
     saving_throws: null    — null
     damage_vulnerabilities: null — null
   traits/actions ВСЕГДА присутствуют как [] (даже пустые).
   bonus_actions/reactions/legendary_actions/mythic_actions/lair_actions
   — null когда отсутствуют.
   Следствие: UI должен проверять три состояния (null / [] / non-empty)
   вместо двух.

10. classes.subclass_title.ru — не переведено в 5 классах
    Затронуты: druid.json, monk.json, paladin.json, ranger.json, rogue.json
    Проблема: subclass_title.ru = subclass_title.en (английский текст):
      druid:  "Druid Circle" (вместо "Круг друида")
      monk:   "Monastic Tradition" (вместо "Монашеская традиция")
      paladin: "Sacred Oath" (вместо "Священная клятва")
      ranger: "Ranger Conclave" (вместо "Конклав следопыта")
      rogue:  "Roguish Archetype" (вместо "Воровской архетип")

11. class_table column names — ru: null в 3 классах
    Затронуты: druid.json, paladin.json, ranger.json
    Проблема: Колонки ячеек заклинаний (slot1, slot2, ...) имеют
    "name": {"en": "1", "ru": null} вместо {"en": "1", "ru": "1"}.
    Остальные классы (artificer, bard, cleric, sorcerer, warlock, wizard)
    имеют "ru": "1", "ru": "2" и т.д.

12. maneuvers — maneuver_zasada.json отсутствует поле cost
    Затронуты: maneuvers/maneuver_zasada.json
    Проблема: Все 19 остальных maneuver-файлов содержат "cost".
    maneuver_zasada.json — не содержит.
    Следствие: UI покажет манёвр без стоимости.

13. schems — name.en в заголовках таблиц переключается с русского на английский
    Затронуты: schems/artificer_l2_*.json, l6_*.json, l10_*.json, l14_*.json
    Проблема:
      l2:  column "schems".name.en = "Схема магического предмета" (русский)
          column "attunement".name.en = "attunement" (lowercase)
      l6:  (те же значения)
      l10: column "schems".name.en = "Schema" (английский)
           column "attunement".name.en = "Attunement" (capitalized)
      l14: (те же значения что l10)
    Следствие: При en-локали таблицы l2/l6 покажут русский текст
    в заголовках; l10/l14 — английский.

14. schems — description2 отсутствует в l6
    Затронуты: schems/artificer_l6_shemy_magicheskih_predmetov.json
    Проблема: l2, l10, l14 содержат description2; l6 — нет.
    Следствие: UI покажет примечание для l2/l10/l14, но не для l6.

15. invocations/metamagics/maneuvers/schems — отсутствуют type, format_version, source
    Затронуты: 62 JSON-файла (28+10+20+4)
    Проблема: Все остальные категории (spells, items, classes, species,
    backgrounds, feats, conditions, monsters, mechanics, features,
    subclasses) имеют поля "type" и "format_version".
    Эти 4 категории — не имеют.
    Следствие: ContentRepository.findType() не может определить тип
    по полю "type" в JSON; работает только через имя директории.

16. backgrounds — haunted_one.json и svoya_predystoriya.json отсутствует поле feat
    Затронуты: backgrounds/haunted_one.json, backgrounds/svoya_predystoriya.json
    Проблема: Все остальные 59 background-файлов содержат "feat" (fullId).
    Эти 2 — нет (у них есть "feature", но нет "feat").
    Следствие: UI не сможет отобразить ссылку на черту для этих
    предысторий.

17. items — magic field отсутствует на non-magic предметах
    Затронуты: ~197 из 685 item-файлов
    Проблема: Magic-предметы имеют "magic": true. Non-magic —
    не имеют поля "magic" вообще (вместо "magic": false).
    Модель имеет default false, но отсутствие поля vs false
    создаёт двусмысленность при ручном анализе JSON.

18. items — cost.amount: float в non-magic, integer в magic
    Затронуты: items/*
    Проблема: non-magic предметы: "amount": 15.0 (float)
    magic-предметы: "amount": 400 (integer)
    Модель Cost.amount: Double, но JSON-формат несогласован.

19. items — scimitar.json и glaive.json имеют category: "adventuring_gear"
    Затрануты: items/scimitar.json, items/glaive.json
    Проблема: Эти файлы содержат damage-блок и weapon-properties,
    но category = "adventuring_gear" вместо "weapon".
    Следствие: Предмет попадёт в неправильную категорию при фильтрации.

20. classes — monk.json отсутствует multiclass_requirements
    Затронуты: classes/monk.json
    Проблема: Все остальные 12 классов содержат multiclass_requirements.
    monk — нет.
    Следствие: Невозможно отобразить требования мультиклассирования для монаха.

21. classes — feature IDs: смесь английских и русских транслитераций
    Затронуты: classes/sorcerer.json, classes/warlock.json
    Проблема: Sorcerer и Warlock используют английские имена в feature IDs:
      "phb2024:sorcerer_l1_spellcasting", "phb2024:warlock_l1_pact_magic"
    Все остальные классы — русскую транслитерацию:
      "phb2024:artificer_l1_magiya_veschey", "phb2024:barbarian_l1_yarost"
    Следствие: Нет единого паттерна для программного построения ID.


B) Дубли и конфликты
---------------------

1. Дубликаты ID в манифесте — 5 конфликтов
   Затронуты: manifest.json
   Проблема: 5 ID встречаются в двух разных категориях одновременно:

   | ID             | Категория 1    | Категория 2  | name.ru 1   | name.ru 2     |
   |----------------|----------------|-------------|-------------|---------------|
   | guard          | backgrounds    | monsters    | Стражник    | Страж         |
   | mist_wanderer  | backgrounds    | monsters    | Странник... | Скиталец...   |
   | noble          | backgrounds    | monsters    | Дворянин    | Дворянин      |
   | piercer        | feats          | monsters    | Пронзатель  | Пронзатель    |
   | tough          | feats          | monsters    | Крепкий     | Громила       |

   Следствие: ContentRepository.entryIndex — Map<String, Pair<String, ManifestEntry>>,
   где ключ = "$packId:${entry.id}". При коллизии последний записанный
   объект затирает предыдущий. Порядок итерации по категориям:
   spells → items → classes → species → backgrounds → feats → conditions
   → monsters → mechanics → glossary → features → subclasses.
   backgrounds ИДЁТ ДО monsters, значит при дубликате guard/noble/mist_wanderer
   monsters-запись затрёт backgrounds-запись. Для piercer/tough — feats ИДЁТ ДО
   monsters, значит monsters-запись затрёт feats-запись.
   Итог: guard/noble/mist_wanderer нельзя открыть как background;
   piercer/tough нельзя открыть как feat.

2. Формат ID в манифесте — 114 с префиксом, 2581 без
   Затронуты: manifest.json
   Проблема: 114 ID в категориях subclasses (20) и features (94)
   имеют формат "phb2024:xxx", а остальные 2581 — bare "xxx".
   Префиксные ID принадлежат warlock (subclasses + features) и
   artificer/fighter (subclasses) + sorcerer/warlock (features).
   ContentRepository.fullId = "$packId:${entry.id}", что даёт
   "phb2024:phb2024:warlock_great_old_one" — двойной префикс.

3. JSON filename vs id — 4 mismatches в subclasses
   Затронуты:
     subclasses/artificer_alhimik.json     → id: "phb2024:artificer_alhimik"
     subclasses/artificer_artillerist.json → id: "phb2024:artificer_artillerist"
     subclasses/artificer_boevoy_kuznets.json → id: "phb2024:artificer_boevoy_kuznets"
     subclasses/artificer_bronnik.json     → id: "phb2024:artificer_bronnik"
   (Также fighter_banneret, fighter_champion и др., всего ~20 с префиксом)
   Проблема: ContentRepository.loadObject() строит путь:
     "packs/$packId/$dirName/$objectId.json"
   где objectId извлекается из fullId после ':'. Для fullId
   "phb2024:phb2024:artificer_alhimik" — objectId будет
   "phb2024:artificer_alhimik" (с двоеточием), путь будет
   "packs/phb2024/subclasses/phb2024:artificer_alhimik.json" — файл не найден.

4. spells.subclasses — русские имена вместо fullId
   Затронуты: spells/* (181 файл с subclasses)
   Проблема: spell.classes — массив fullId ("phb2024:wizard").
   spell.subclasses — массив русских имён:
     ["Артиллерист", "Круг земли", "Домен света"] — fireball.json
     ["Бронник"] — magic_missile.json
   Несовместимость: classes — structured references, subclasses — display names.
   Следствие: Невозможно программно резолвить subclass по ID;
   ItemLinkifier не найдёт совпадений.

5. species.subspecies — absent vs null
   Затронуты: 15 из 19 species-файлов не содержат subspecies
   Проблема: 4 файла (dragonborn, elf, gnome, tiefling) содержат
   "subspecies": [...]. Остальные 15 — поле отсутствует.
   Модель имеет subspecies: List<SubspeciesInfo>? = null.
   Но species.darkvision ВСЕГДА присутствует (0 когда нет).
   Несогласованность: для darkvision — 0 вместо null; для subspecies —
   absent вместо null. Нет единого паттерна.

6. items.subcategory — string в 559+, array в 1
   Затронуты: items/adamantine_weapon.json
   Проблема: subcategory: ["simple_melee", "martial_melee", "ammunition"]
   в одном файле; "subcategory": "martial_melee" (строка) во всех остальных.
   StringOrListSerializer работает, но не позволяет отличить
   "одна категория" от "несколько категорий" при сериализации.

7. backgrounds — equipment_items отсутствует во всех файлах
   Затронуты: backgrounds/* (61 файл)
   Проблема: Модель Background содержит equipment_items: List<String>.
   Ни один JSON-файл не содержит этого поля.
   Модель содержит избыточное поле, не используемое в данных.

8. schems — source, tags, references в модели, но не в JSON
   Затронуты: schems/* (4 файла)
   Проблема: Schems-модель содержит source, tags, references, description2.
   JSON-файлы содержат только: id, name, table, description2.
   Поля source, tags, references — избыточны в модели.

9. features — origin, requirements, table, description2 в модели, но не в JSON
   Затронуты: features/* (635 файлов)
   Проблема: Feature-модель содержит origin, requirements, table, description2.
   Ни один feature-JSON не содержит этих полей.
   Модель обещает то, чего нет в данных.


C) Нестабильные сущности
-------------------------

1. GameClass — 6 type-specific полей не масштабируются
   Поля: invocations, metamagics, wild_magic, maneuvers, schems, subclasses
   Проблема: Каждый новый тип class-specific особенности требует
   добавления нового List<String> поля в GameClass. Уже сейчас:
     warlock  → invocations
     sorcerer → metamagics, wild_magic
     fighter  → maneuvers
     artificer → schems
   Добавление класса с "infusions" (например) потребует изменения модели
   и всех 13 JSON-файлов классов.
   Формат: НЕ расширяется без изменения модели.

2. Spell.subclasses — display names вместо fullId
   Проблема: spell.subclasses содержит русские имена, а spell.classes —
   fullId. Это структурный конфликт: нельзя резолвить subclass по ID,
   нельзя использовать ItemLinkifier, нельзя фильтровать по subclass ID.
   Формат: НЕ расширяется без миграции 181 JSON-файла.

3. casting_time / duration — свободный текст
   Проблема: Нет структуры для программной обработки. Фильтр по
   "Бонусное действие" требует точного совпадения строки, которая
   может быть "Бонусное действие" или "Бонусным действием" (падежи).
   Формат: НЕ расширяется без полной переделки 412 spell-файлов.

4. damage_vulnerabilities — смешанный язык
   Проблема: Русский текст ("к урону Огонь") vs английские
   идентификаторы в resistances/immunities. Два разных when-блока
   для локализации. Некоторые значения — описания механики, а не типы.
   Формат: НЕ расширяется без миграции 28 monster-файлов.

5. ManifestObjects — 4 категории не индексируются
   Проблема: invocations, metamagics, maneuvers, schems — директории
   существуют, но в манифесте отсутствуют. Невозможно перечислить,
   найти тип или отрезолвить ссылку.
   Формат: НЕ расширяется без изменения ManifestObjects и пересборки
   manifest.json.

6. key_attributes — Map<String, String> с русскими ключами
   Проблема: Ключи Map — русские строки, не LocalizedString.
   Нельзя отобразить на английском, нельзя программно извлечь
   конкретный атрибут.
   Формат: НЕ расширяется без миграции 13 class-файлов.

7. source.book — 3 формата + 2 кодировки апострофа
   Проблема: Нельзя сгруппировать объекты по источнику без нормализации.
   Формат: НЕ расширяется без миграции всех 2695 JSON-файлов.

8. treasure/equipment — строки с запятыми вместо массивов
   Проблема: "Личные , Магические" — строка, а не ["Личные", "Магические"].
   Нельзя перечислить или отфильтровать.
   Формат: НЕ расширяется без миграции 99 monster-файлов.


D) Приоритетные стандартизации
-------------------------------

Приоритет 1 (критичный — блокирует функционал):
  1.1. Дубликаты ID в манифесте (5 конфликтов)
       Действие: Переименовать ID в одной из категорий.
       Например: monsters/guard → monsters/guard_npc, monsters/noble → monsters/noble_npc
       Объём: 5 JSON-файлов + manifest.json

  1.2. Формат ID в манифесте: phb2024: prefix в subclasses/features
       Действие: Убрать префикс "phb2024:" из entry.id в манифесте.
       ContentRepository уже строит fullId как "$packId:${entry.id}",
       префикс создаёт двойной "phb2024:phb2024:xxx".
       Объём: 114 записей в manifest.json

  1.3. JSON id vs filename в subclasses (префикс в id)
       Действие: Убрать префикс "phb2024:" из id-поля в 20 subclass JSON-файлах.
       Объём: 20 JSON-файлов

Приоритет 2 (высокий — ломает данные):
  2.1. spells.subclasses: русские имена → fullId
       Действие: Заменить ["Артиллерист"] на ["phb2024:artificer_artillerist"].
       Объём: 181 spell-файл. Требует mapping русских имён к fullId.

  2.2. source.abbreviation: единый формат
       Действие: Выбрать один формат (рекомендуется "PHB2024" без пробела)
       и применить ко всем файлам.
       Объём: все 2695 JSON-файлов (массовый find-replace)

  2.3. source.book.en: единый формат
       Действие: Выбрать "Player's Handbook 2024" (без скобок)
       и единый апостроф.
       Объём: все 2695 JSON-файлов (массовый find-replace)

  2.4. maneuver_zasada.json: добавить поле cost
       Объём: 1 файл

  2.5. backgrounds: haunted_one.json и svoya_predystoriya.json: добавить feat
       Объём: 2 файла

  2.6. classes/monk.json: добавить multiclass_requirements
