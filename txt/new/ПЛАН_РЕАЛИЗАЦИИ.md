# План реализации нового мастера создания персонажа и листа персонажа

## Обзор изменений

Текущий мастер создания персонажа (`CharacterCreateFragment.kt`) — это один фрагмент с 7 шагами (0–6), где каждый шаг рендерится программно через `renderStep()`. Все шаги используют простые кнопки. Данные хранятся в `CharacterData.kt`.

Новый дизайн (по макетам из `txt/new/`):
- **6 экранов создания** в порядке: Характеристики → Виды → Происхождения → Классы → Умения класса → Черты
- **Лист персонажа** с 4 вкладками: Основное, Умения, Заклинания, Инвентарь
- Drag-and-drop для характеристик
- Режимы генерации характеристик: Кастом, 4d6-less, Buy (point-buy)
- Карточки с раскрытием для видов/происхождений/классов/умений/черт
- Поиск, фильтр, сортировка на экранах видов/происхождений

### 4.1. Экран 1 — Характеристики

**Файл:** Новый layout `fragment_create_abilities.xml` + рендер в `CharacterCreateFragment.kt`

**Структура экрана:**
1. **Поле имени** (EditText) вверху — "Имя: ..........."
2. **6 слотов характеристик** (пунктирная рамка) — цели для drag-and-drop:
   - Сила, Ловкость, Телосложение (ряд 1)
   - Интеллект, Мудрость, Харизма (ряд 2)
3. **6 контролов характеристик** (снизу):
   - Каждый: кнопка "+" | значение (8) | кнопка "-"
   - Расположены в 2 ряда по 3
4. **Счётчик очков** "0/27" — виден только в режиме Buy
5. **3 кнопки режима**: Кастом | 4d6-less | Buy (MaterialButtonToggleGroup)
6. **Кнопки навигации**: Назад / Далее

**Логика:**
- **Кастом**: игрок вручную ставит значения через +/-. Ограничения: 3–20.
- **4d6-less**: бросок 4d6, отбрасывание наименьшего, 6 результатов. Игрок перетаскивает результаты в слоты.
- **Buy**: point-buy система (27 очков). Стоимость повышения:
  - 8→9: 1, 9→10: 1, 10→11: 1, 11→12: 1, 12→13: 2, 13→14: 2, 14→15: 3, 15→16: 4
  - Минимум 8, максимум 15 (до расовых бонусов)
- **Drag-and-drop**: характеристики из нижних блоков перетаскиваются в верхние слоты. В режиме 4d6-less — броски перетаскиваются в слоты.

**Реализация drag-and-drop:**
- Использовать Android `View.DragShadowBuilder` + `View.OnDragListener`
- Или библиотеку (но предпочтительно нативный подход)
- Нижние блоки — drag sources, верхние слоты — drop targets

**Файлы:**
- Создать `feature/characters/.../res/layout/fragment_create_abilities.xml`
- Метод `renderAbilitiesStep()` в `CharacterCreateFragment.kt`

## Часть 5. CharacterCreateFragment.kt — полная переработка

### 5.1. Изменение шагов

Текущие шаги (0–6):
```
0: Species → 1: Background → 2: Class → 3: Abilities → 4: Equipment → 5: Spells → 6: Details
```

Новые шаги (0–5):
```
0: Abilities (Характеристики) → 1: Species (Виды) → 2: Background (Происхождения) → 3: Class (Классы) → 4: Features (Умения класса) → 5: Feats (Черты)
```

### 5.2. Архитектура

Вместо программного рендера через `renderStep()` → использовать отдельные Fragment/View для каждого шага, или оставить программный рендер но с новыми layout.

**Рекомендация:** Оставить программный рендер в одном фрагменте (проще для навигации между шагами), но каждый шаг рендерит свой layout из XML.

### 5.3. ViewModel

**Файл:** `CharactersViewModel.kt`

Добавить:
- `CharacterCreateState` вместо `CharacterData` для wizard state
- Методы для drag-and-drop логики
- Методы для point-buy расчётов
- Методы для 4d6-less бросков
- Метод для финального сохранения: конвертация `CharacterCreateState` → `CharacterData`

### 5.4. Drag-and-Drop реализация

**Подход:** Нативный Android Drag-and-Drop API

1. **Drag source** (нижние блоки характеристик):
   - `View.setOnLongClickListener` → начало перетаскивания
   - `View.startDragAndDrop()` с `ClipData` содержащим id характеристики и значение

2. **Drop target** (верхние слоты):
   - `View.setOnDragListener`
   - `DragEvent.ACTION_DROP` → получить данные из `ClipData`, установить значение в слот

3. **Визуальная обратная связь**:
   - Drag shadow показывает значение
   - Подсветка слота при наведении
   - Анимация при успешном drop

**Файл:** Создать `DragDropHelper.kt` в `core/ui/`

- Навыки и спасброски из `CharacterData.skills` и `CharacterData.savingThrows`

### 6.3. Вкладка 2 — Умения

**Layout:** `fragment_sheet_abilities.xml`

**Структура:**
1. **Умения класса**: раскрывающиеся карточки (как в мастере создания, но без dropdown — показывается выбранное значение)
2. **Умения вида**: карточки с чертами вида
3. **Черты**: карточки с описаниями

### 6.4. Вкладка 3 — Заклинания

**Layout:** `fragment_sheet_spells.xml`

**Структура:**
1. **Таблица заклинательных характеристик** (3 строки × 3 колонки):
   - Мод. закл. характеристики | +0
   - Сл. спасброска заклинаний | 10
   - Бонус атаки заклинаниями | +2

   - Каждый уровень: название + звёзды (заполненные/пустые)
3. **Список заклинаний**: карточки с цветной левой полосой (по школе магии)

**Данные:**
- Из `CharacterData.spells` и `CharacterData.spellSlots`
- Заклинательная характеристика из `class.spellcasting.ability`

### 6.5. Вкладка 4 — Инвентарь

**Layout:** `fragment_sheet_inventory.xml`

**Структура:**
1. **Экипировано**:
   - Доспех (dropdown с раскрытием описания)
   - Щит (dropdown)
   - Оружие 1, Оружие 2 (dropdown)
   - Магические предметы (dropdown)

## Часть 10. Примечания

1. **Никакой сложной математики**: все значения (скорость, КЗ, модификаторы) подтягиваются из JSON или вычисляются по простым формулам. Игрок сам учитывает влияние доспеха на скорость.

2. **Данные из JSON**: все тексты, описания, списки навыков/инструментов/снаряжения берутся из JSON карточек. UI только отображает и позволяет выбирать.

3. **Редактирование и левел-ап**: не реализуются в этом этапе. Кнопки "Level-Up" и "Ред." на листе персонажа будут заглушками.

4. **0/27 счётчик**: отображается только в режиме Buy. В режимах Кастом и 4d6-less скрыт.

5. **Справочник vs Создание**: часть данных в справочнике отображается как текст (например, "Увеличение характеристик: выберите две"), а в мастере создания — как интерактивные элементы (dropdown, radio). Это достигается через разные UI-компоненты для одних и тех же JSON-данных.
